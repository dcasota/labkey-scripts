### PR-030

**Publish outbox**

- **Branch**: `pr-030-publish-outbox`
- **Size**: M (3-5 days)
- **Depends on**: PR-013
- **Status**: todo
- **Requirements**: FR-021, FR-055, PRO-003

Implements ADR-0005: the transactional queue that decouples OSM writes from LabKey publishing.

**Acceptance criteria**

- [ ] An outbox row commits in the same transaction as the domain write, proven by a test that kills the process after commit and observes the row present
- [ ] PHI is stripped when the row is built, not at publish time, so no payload containing PHI is ever queued
- [ ] The worker claims rows with SELECT FOR UPDATE SKIP LOCKED and two workers never publish the same row
- [ ] A failed publish stores the HTTP status and body and is retried with capped exponential backoff
- [ ] A row exhausting its attempts remains FAILED and is never silently dropped
- [ ] The age of the oldest pending row is exposed as a metric

### PR-031

**LabKey bridge: sample publishing (P-LK-SAMPLE)**

- **Branch**: `pr-031-bridge-samples`
- **Size**: L (5-10 days)
- **Depends on**: PR-030,PR-001
- **Status**: todo
- **Requirements**: CON-008, FR-009, FR-051, FR-052, FR-053, FR-054

The first publish pipeline: create the container and sample type domain in LabKey CE, then import samples idempotently.

**Acceptance criteria**

- [ ] The bridge authenticates with an API key restricted to EditorWithoutDelete
- [ ] A sample type domain is created in LabKey with the OSM fields plus osm_id and a barcode field using the storageUniqueId concept URI
- [ ] Re-publishing the same sample upserts on osm_id and creates no duplicate, proven by a test that publishes twice
- [ ] A response lost in transit followed by a retry converges rather than duplicating
- [ ] Lineage is published as lookups and storage_path as a plain string, with the map remaining in OSM
- [ ] Publishing uses query-import.api, not the non-existent query-importData.api
- [ ] A LabKey 4xx is captured with its body and surfaced in the FAILED row
- [ ] The pipeline never calls addWebPart

### PR-033

**MCP server: read tools**

- **Branch**: `pr-033-mcp-read`
- **Size**: M (3-5 days)
- **Depends on**: PR-008
- **Status**: todo
- **Requirements**: CON-005, CON-012, FR-008, FR-044, FR-064, FR-065

Implements ADR-0006: the MCP transport as an HTTP client of the REST API, starting with read-only tools.

**Acceptance criteria**

- [ ] Each tool is a thin translation onto a REST call authenticated as the agent principal, with no direct domain access
- [ ] An agent cannot read anything the same principal could not read over REST, proven by a test with a restricted principal
- [ ] Every invocation emits llm.invoke carrying model_id and request_id
- [ ] The tool allowlist is bound to the session at authentication time and is not derived from any content the agent reads
- [ ] A document instructing the agent to use an unlisted tool has no effect, covered by an injection test
- [ ] Errors are translated without leaking data the principal cannot see

### PR-034

**MCP server: guarded write tools**

- **Branch**: `pr-034-mcp-write`
- **Size**: M (3-5 days)
- **Depends on**: PR-033
- **Status**: todo
- **Requirements**: CON-010, FR-045, FR-046, PRO-005, PRO-007

Write tools with the confirm and scope requirements of spec 10, and the absolute prohibitions of spec 18.2.

**Acceptance criteria**

- [ ] A destructive tool requires both confirm=true and the osm.admin.write scope, and confirm is a distinct explicit argument
- [ ] Discard, ship, lock, ELN signing and permission changes are not present in the tool list at all
- [ ] Every agent-initiated write is audited with actor_type set to mcp and correlated with its llm.invoke event
- [ ] At most one unsafe write chain is permitted per turn and a second is refused
- [ ] A test asserts that each prohibited operation has no corresponding tool, so the prohibition cannot be weakened by adding one later
